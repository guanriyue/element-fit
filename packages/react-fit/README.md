# React Fit

`@guanriyue/react-fit` 提供一组根据元素实际可用空间执行测量、溢出判断和布局切换的 React 组件。

## 视窗优先级测量调度

当组件需要根据元素与视窗的距离拆分测量任务时，统一使用 viewport-priority scheduling。该机制只调整
任务执行优先级，不改变组件的测量结果：

- near 任务在 microtask 中批量执行，优先完成视窗附近的测量和状态更新。
- far 任务优先通过 `requestIdleCallback` 分批执行，降低大量离屏节点同时测量造成的主线程压力。
- 浏览器不支持 `requestIdleCallback` 时，far 任务回退到 `requestAnimationFrame`；如果 RAF 也不可用，
  则回退到 timer。
- 同一个稳定 task 在等待期间只保留一次。重新调度时可以在 near/far 队列之间迁移，也可以在失效后取消。

far 任务每个批次最多处理有限数量的节点，并为 idle callback 设置 300ms timeout。timeout 只用于避免页面
持续繁忙时任务无限饥饿，不代表 300ms 是适合所有任务规模和页面负载的延迟或执行预算。大量 far 任务仍
可能经过多个批次才能完成。

### 优先级采样

组件在实际需要调度测量时，通过 `getBoundingClientRect()` 采样目标元素与视窗的距离。不同组件可以选择
不同的采样元素和 near margin；这些差异由对应组件文档说明。

优先级不是持续状态。组件不会使用 `IntersectionObserver` 跟踪元素可见性，单独滚动页面通常不会触发
重新测量，也不会重新划分已经排队任务的优先级。待执行任务本身是可以在较短时间内完成的小型任务，
near/far 分级的目标是削平短时间内大量测量和浏览器布局造成的峰值，而不是长期暂停离屏节点。

### 用户可见的延迟

near 范围内存在大量节点时，仍可能形成较大的同步任务批次。视窗优先级只能把远处任务延后，不能消除
近视窗任务自身的 DOM、样式计算和布局成本。

far 节点的首次测量和后续状态更新可能延迟到 idle batch。组件在首次可信测量前使用什么默认状态，以及
这种延迟会影响哪些 UI，由对应组件文档说明。业务不应依赖所有离屏组件在同一帧内完成测量。
