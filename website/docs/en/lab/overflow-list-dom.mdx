# OverflowList DOM Scheduling Experiment

This internal stress-test implementation exists only in the website and is not part of the `@guanriyue/react-fit` public API. It uses the same geometry algorithm, layout-task batching, and viewport priority as the public OverflowList, but its measurement stages modify DOM directly and do not call React `flushSync`.

Items and Accessories always retain their DOM in this experiment and enter or leave layout through the native `hidden` attribute. Accessory must always render and use a constant-width ellipsis button; its measured width does not depend on the latest React render of `overflowItems`. These constraints allow the experiment to avoid a synchronous React commit and do not represent the public component's API contract.

The page provides the same instance counts, short and long labels, action addition and removal, container width switches, and continuous width animation as the public OverflowList stress test. It can be used to compare persistent DOM with React conditional mounting.
