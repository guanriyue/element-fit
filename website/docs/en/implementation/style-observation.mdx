# Observing Style Changes and Invalidating Measurements

A layout measurement remains valid only while a set of assumptions holds: the nodes are unchanged, the content is unchanged, available space is unchanged, and the styles involved in layout continue to produce the same geometry.

Browsers can read computed styles but provide no stable, general notification for computed-style changes. Element Fit therefore combines three categories of observable signals instead of attempting to observe every style source:

| Signal | Changes it can detect | Information it cannot express |
| --- | --- | --- |
| React and component state | Props, data, options, and node registration | Changes outside React |
| `ResizeObserver` | Final changes to element boxes | Content and typography changes that preserve box size |
| `MutationObserver` | DOM attributes, text, and child nodes | Computed results from external stylesheets, inheritance, and media conditions |

These signals are not fallbacks for one another. They observe application state, layout results, and DOM causes respectively, and together determine whether an existing measurement remains reliable.

## Browsers have no general style observer

`getComputedStyle()` reads computed styles but does not notify consumers when its results change. Final style values can come from the node, ancestors, stylesheets, inheritance, media queries, container queries, and pseudo-elements. Browsers do not expose the complete dependency graph among these values.

The CSSWG has a [`ComputedStyleObserver` proposal](https://github.com/w3c/csswg-drafts/issues/8982) intended to provide computed-style change notifications similar to other Observer APIs. Callback timing, observed properties, and the performance model are still under discussion, so the proposal cannot serve as a component library's runtime foundation.

Another approach calls `getComputedStyle()` every frame and compares selected properties. This creates continuous style-read cost and still requires the component to know every CSS property that can affect the measurement. Fonts, writing modes, box models, and subtree layout have combinatorial relationships; comparing a selected property set cannot provide generally correct dependency tracking.

Element Fit uses observable-change-driven invalidation: it discards an old result and schedules measurement only when the component can identify an input change or when the browser reports a relevant box-size change.

## ResizeObserver observes layout results

[`ResizeObserver`](https://drafts.csswg.org/resize-observer/) observes boxes generated by elements. It directly answers two common measurement questions:

- Did a container's content box change, meaning the space available to content changed?
- Did content's border box change, meaning the space actually occupied by the element changed?

Callbacks prefer `contentBoxSize` or `borderBoxSize` from `ResizeObserverEntry`. The browser already supplies these values with the notification, avoiding another `getComputedStyle()` or synchronous geometry call for the same size. Compatibility paths can fall back to `contentRect` or other geometry.

ResizeObserver observes results, not the styles that caused them. If the font inside a fixed-width element changes, the element box can remain unchanged while its text changes from fitting to overflowing; this change does not necessarily resize the target element. A child size change that does not propagate to the observed element's box has the same boundary.

ResizeObserver can therefore be authoritative for size-cache updates, but cannot act as a computed-style observer.

## MutationObserver observes DOM causes

[`MutationObserver`](https://dom.spec.whatwg.org/#mutationobserver) reports attribute, text, and child-node changes. A measurement component chooses the smallest observation scope appropriate for its content:

```ts
const contentOptions = {
  subtree: true,
  childList: true,
  characterData: true,
} satisfies MutationObserverInit;
```

This configuration fits content-oriented components: text edits, node insertion, and node removal all invalidate existing content measurements. It does not report `class` or `style` changes because `attributes` is disabled.

An attribute-oriented component can observe only attributes known to affect measurement:

```ts
const textareaOptions = {
  attributes: true,
  attributeFilter: [
    'class',
    'cols',
    'dir',
    'id',
    'lang',
    'placeholder',
    'rows',
    'wrap',
  ],
} satisfies MutationObserverInit;
```

An allowlist prevents `aria-*`, `data-*`, and unrelated attributes from repeatedly invalidating measurement. After a notification, an attribute signature can also be compared to skip records whose values did not actually change.

MutationObserver observes DOM mutations, not CSS computed results. An ancestor class change, external stylesheet update, or media-query transition does not automatically become a record merely because a descendant is observed. Only when the change also alters a ResizeObserver target's box can the size signal cover that part of the result.

## React provides explicit input signals

When a component already knows that a change must affect measurement, explicit invalidation is more accurate than widening DOM observation. Examples include:

- A controlled value, default value, or automatic-sizing option changes.
- A measurement mode or precision option changes.
- An Item, Accessory, Spacer, or another participating node mounts, unmounts, or is replaced.
- Business data changes and produces new content nodes.

Props, effects, event handlers, or ref registration pass these signals directly to the store. They do not wait for the browser to infer a cause and do not add unrelated DOM mutations to the measurement path.

A measurement system can then form an explicit data flow:

```text
observable signal
  → invalidate cache
  → merge and schedule measurement
  → read the latest layout
  → commit only a still-valid result
```

Invalidating and measuring immediately are separate actions. Observer callbacks declare an old result unreliable; the scheduler merges repeated requests that arrive close together. Before measurement starts, a newer signal can replace an older pending task. When measurement ends, node and option identities must still match the state from which the task was created.

## Filter the component's own DOM mutations

Some measurements temporarily mount mirror nodes or insert internal nodes such as Spacer and Suffix into Root. If Root also has a MutationObserver, the component's own DOM writes produce mutation records.

A `measuring` boolean cannot filter these records reliably. MutationObserver callbacks are delivered asynchronously; by the time a record reaches the callback, the current measurement transaction may have ended and the flag may already be reset.

Before an internal node participates in DOM, Element Fit records that node and its subtree in a `WeakSet<Node>`:

1. Ignore a record whose target belongs to a marked subtree.
2. Ignore a `childList` record when all added and removed nodes come from marked subtrees.
3. If the same record batch contains any business-content change, still invalidate measurement.

WeakSet serves two purposes: markings do not strongly retain removed internal nodes, and a delayed record can still be recognized by node identity after removal from DOM. This avoids measurement loops from the component's writes without overlooking real content changes mixed into the same batch.

## Invalidation must match cache dependencies

Caching can skip repeated measurement, but every reuse rule must correspond to an explicit invalidation signal. A typical overflow cache might depend on:

- Current Root and Content node identity.
- Root's content-box width.
- Text and child-node structure in Content.
- Component options that affect the decision method.

Node replacement, content mutation, or option changes clear the cache directly. Root resize updates width and either reuses or remeasures according to whether the existing result can be inferred monotonically. Whether a Content resize invalidates the cache depends on the cache semantics; a notification alone is not a reason to clear every result.

Similarly, a measurement component can receive a ResizeObserver callback after writing its own size. The callback should compare the dimension that is truly an input. A Textarea writes height from its measurement result, while text wrapping depends on content-box width. Remeasuring only when width changes avoids a feedback loop from the height commit.

## Observable boundaries

Combining ResizeObserver, MutationObserver, and explicit state is still not complete computed-style dependency tracking. The following changes are detected only if they produce a DOM mutation in the observed scope, an explicit input signal, or a resize of the target box:

- External stylesheet rules change.
- An ancestor's class or style changes.
- Inherited styles, media queries, or container queries switch.
- Font metrics change while the observed element's box remains the same.
- Pseudo-element content or another layout input outside the target DOM subtree changes.

Polling computed styles continuously to cover these cases would turn finite layout measurement into permanent work and still could not derive every CSS dependency automatically. Element Fit retains this observation boundary so that every invalidation has an identifiable source.

## Current applications

- InlineOverflow observes Root and Content sizes and observes text and child-node changes in the Content subtree.
- LineClamp observes Root size and content mutations while filtering internal records from Spacer, Suffix, and measurement mirrors.
- Textarea combines controlled values, input events, options, style props, size changes, and an attribute allowlist.
- FitSwitch, CompactGrid, and OverflowList primarily rely on registered-node lifecycle and size signals instead of broad DOM observation for every style change.

The selected signals differ by component, but follow one rule: define the dependencies of a measurement result first, then provide invalidation paths for dependencies that can be observed.
