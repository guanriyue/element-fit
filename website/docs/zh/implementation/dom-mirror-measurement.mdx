# DOM 镜像测量

浏览器的几何 API 只能读取已经形成的布局。它们适合回答“当前节点占据多大空间”，却不能直接回答反事实问题：如果内容使用另一种宽度、移除某个装饰节点、解除高度限制，最终会形成怎样的布局？

DOM 镜像测量会创建一个临时节点，复制影响目标排版的内容与样式，让浏览器真实完成另一种布局，再读取几何结果。它不是用 JavaScript 重写 CSS 布局算法，而是为浏览器构造一个可测量的假设状态。

## 镜像必须参与布局

`display: none` 的节点不生成目标布局盒，`scrollHeight`、Range rect 和元素几何都无法表达它显示后的排版结果。镜像需要保持可布局，同时不能出现在页面视觉和正常文档流中。

常见的基础样式组合是：

```css
.measure-container {
  position: fixed;
  inset: 0 auto auto 0;
  width: 0;
  height: 0;
  visibility: hidden;
  pointer-events: none;
}
```

CSS 对 `visibility: hidden` 的定义是内容不可见，但生成的盒仍然影响布局。这使它适合作为测量隐藏方式。`position: fixed` 或 `absolute` 把容器移出常规流，零尺寸外壳减少它对页面滚动范围和周围布局的影响。

`visibility` 可以被后代重新设置为 `visible`。测量任意 DOM subtree 时，可以在镜像根上叠加 `opacity: 0`，或者给每个测量节点设置不可覆盖的隐藏样式，避免后代规则让内容意外出现。

镜像不能使用原生 `hidden` 属性作为测量状态，因为该属性通常会通过用户代理样式产生 `display: none`。视觉隐藏、移出常规流和保持布局盒是三个不同要求，需要分别处理。

## 同一文档提供相同布局环境

镜像应使用源节点的 `ownerDocument` 创建，并连接到同一 Document。这样它可以使用相同的字体资源、设备像素环境、书写系统和浏览器布局实现；在 iframe 或多 Document 页面中，也不会错误地把节点挂到全局 `document`。

连接位置会影响 CSS 选择器、继承和包含块。挂到 `body` 下的独立测量容器通常具有稳定、可控的环境，但会失去源节点祖先链提供的上下文。把镜像挂在源节点附近可以保留更多祖先条件，却可能参与局部 flex、grid、container query 或 overflow 布局。

不存在对所有 CSS 都透明的挂载位置。镜像必须明确选择自己要复现的布局输入，并隔离不属于测量目标的环境影响。

## 复制影响尺寸的 computed style

只复制 `className` 不能保证镜像获得相同样式。选择器可能依赖祖先结构、属性、伪类、CSS Modules 生成的作用域或 container query。更稳定的做法是先读取源节点的 computed style，再把影响尺寸的属性写入镜像。

典型的尺寸属性包括：

- 字体族、字号、字重、行高、字距与字体特性。
- `white-space`、换行、断词、hyphens 与 tab size。
- width、box sizing、padding 和 border。
- writing mode、direction、text orientation 与 unicode bidi。
- 会改变滚动尺寸的 scrollbar gutter 和 overflow 行为。

复制范围应由测量问题决定。复制全部 CSS 属性会增加读取与写入成本，也可能带入颜色、动画、transform 或定位等无关甚至有害的视觉状态；属性过少则会让镜像排版偏离源节点。

`getComputedStyle()` 返回的是浏览器解析后的值，但它不是完整布局快照。百分比、包含块、伪元素和某些依赖树结构的行为仍然可能在新位置产生不同结果。复制 computed style 是缩小环境差异，不是把一个 DOM subtree 完整序列化。

## 内容复制与状态复制不同

测量纯文本时，可以把当前字符串写入等价元素。测量混合 DOM 内容时，可以使用 `cloneNode(true)` 复制结构。两种方式都需要区分 markup 与运行时状态：

- DOM clone 不会复制通过 `addEventListener()` 注册的监听器。
- 表单控件的当前编辑状态不一定等同于 attribute 中的初始状态。
- canvas 的绘制位图不属于普通子节点结构。
- selection、focus、scroll position 和自定义元素内部状态不会形成通用副本。
- `::before`、`::after` 等伪元素不属于可克隆的 DOM child。

镜像只需要复现会影响目标几何的状态，不需要变成可交互副本。对于原生表单元素，直接同步当前 value、placeholder、wrap 等测量输入通常比克隆整个节点状态更明确。

## 强制覆盖测量状态

镜像从源节点复制尺寸样式后，还需要覆盖与测量目标冲突的属性。例如测量自然内容高度时，源节点当前的固定高度、最小高度、最大高度或 resize 状态不应继续限制镜像：

```css
.mirror {
  display: block !important;
  height: 0 !important;
  min-height: 0 !important;
  max-height: none !important;
  overflow: hidden !important;
  position: absolute !important;
  visibility: hidden !important;
}
```

这些覆盖不是一套适用于所有镜像的固定模板。测量自然宽度时，强制 `width` 反而会破坏结果；测量指定容器宽度下的换行时，又必须给镜像准确的可用宽度。每种镜像都需要先定义不变量和待求量，再决定哪些源样式保留、哪些状态解除。

## 分阶段挂载和读取

镜像测量天然包含一次 write → read 依赖：

```text
read：读取源节点的内容、尺寸和 computed style
write：配置并挂载镜像
read：读取镜像的 scroll size、rect 或 Range 片段
write：提交结果并清理镜像
```

镜像只有连接到可布局的 Document 后，浏览器才能给出真实结果。挂载后的几何读取通常会触发一次布局结算，因此不能把每个实例完整执行后再处理下一个实例。

多个镜像可以先在各自的 read 阶段准备，再通过 `DocumentFragment` 合并新增节点，一次写入测量容器；随后统一读取全部镜像。这个过程把多个实例的布局依赖对齐到同一个阶段边界，具体调度模型见[布局任务的分阶段批处理](./layout-task-scheduling)。

## 隔离测量容器

共享测量容器可以减少反复创建顶层节点的成本。容器通常会设置尺寸隔离、不可交互和不可访问状态：

```css
.measure-container {
  contain: strict;
  pointer-events: none;
  visibility: hidden;
}
```

`contain: strict` 可以限制镜像布局对页面其他部分的影响，但 containment 也会改变百分比尺寸、intrinsic sizing 和包含块语义。只有镜像已经显式获得测量所需宽高时，才能安全使用这种隔离。

测量节点还应从交互和无障碍树中排除，例如使用 `aria-hidden="true"`、`inert`、负 tab index 或只读状态。具体组合取决于节点类型；视觉不可见并不自动代表无法聚焦或不会被辅助技术访问。

## 短期复用镜像

连续输入、Resize 动画或同一轮批量更新可能在很短时间内反复测量同一个源节点。立即销毁镜像会重复产生 DOM 创建、样式写入、挂载和移除成本。

镜像池可以在一次测量结束后短暂保留节点：

1. 再次测量同一源节点时取回复用。
2. 每次配置都重新覆盖内容和尺寸样式，不把旧测量状态视为可信缓存。
3. 保留期结束后，在后续帧移除仍未被取回的镜像。
4. 清理记录携带节点身份，已经重新启用的镜像不会被旧清理任务误删。

复用的是 DOM 资源，不是几何结果。内容、宽度或样式发生变化时仍然需要重新布局和读取。保留时间也不属于测量语义，只是节点创建成本与驻留 DOM 数量之间的性能取舍。

## cleanup 保证事务闭合

镜像可能在准备、挂载或读取阶段失败，也可能在执行中被取消。清理逻辑不能只放在正常结果提交之后，而应成为测量事务的最终步骤：

- 已挂载的临时节点必须移除或归还池。
- 没有成功连接的节点也不能留在待处理集合中。
- 部分实例失败时，其他镜像仍然可以继续测量。
- 清理自身抛错不能阻止剩余资源释放。

稳定的 cleanup 让测量任务可以安全地跨越多个 DOM stage，而不会把中间镜像变成页面的长期状态。

## 与原地测量的选择

原地测量直接读取当前 DOM，不需要复制样式或建立临时节点，通常成本更低，也能保留完整的祖先环境和运行时状态。它只能回答当前布局已经表达的问题。

镜像测量增加 DOM、样式复制和额外布局成本，但可以隔离当前可见状态，或者构造当前 DOM 中不存在的布局条件。两者的选择取决于问题是否属于反事实布局，而不是某一个几何 API 是否足够精确。

## 能力边界

- 镜像必须真实参与布局，不能通过 `display: none` 隐藏。
- 挂载位置、祖先选择器、继承和 container query 可能使镜像偏离源环境。
- computed style 复制无法完整复现伪元素、树结构依赖和所有 intrinsic sizing 条件。
- DOM clone 不等于运行时状态副本，复杂表单、canvas 和自定义元素需要单独处理。
- containment、固定定位和强制尺寸都会改变布局，只能在符合测量模型时使用。
- 镜像几何读取仍可能触发同步布局，需要和 DOM 写入分阶段执行。
- 复用镜像只能减少资源创建，不能复用已经失效的几何结果。

DOM 镜像测量的核心是让浏览器计算一个受控的假设布局：镜像必须足够接近目标排版，同时又要与页面视觉、交互和正常文档流隔离。
