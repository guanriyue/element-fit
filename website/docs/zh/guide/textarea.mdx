# Textarea

`Textarea` 在原生 `<textarea>` 的基础上提供可选的自动高度能力。未启用 `autoSize` 时，组件保持原生尺寸行为；启用后，组件根据当前内容、排版样式和可用宽度计算高度。

组件只接管自动测得的行内 `height`。输入状态、校验、滚动、裁切和 resize 策略仍由原生属性、表单状态与调用方样式控制。

## 适用场景

Textarea 适合评论框、备注、表单描述和其他需要随内容增长的多行输入：

- 输入内容增加或减少时自动调整高度。
- 容器宽度变化、文本重新换行时重新计算高度。
- 使用最小和最大行数限制伸缩范围。
- 保留原生 `textarea` 的受控、非受控和表单行为。

需要由用户自由拖动并长期保留固定高度时，可以不启用 `autoSize`。自动高度不会根据父容器高度分配空间，也不替代编辑器中的虚拟滚动或复杂内容布局。

## 自动高度模式

传入 `autoSize` 或 `autoSize={{}}` 会启用自动高度。没有行数上限时，Textarea 会随着内容继续增高：

```tsx
<Textarea autoSize />
```

使用 `minRows` 和 `maxRows` 可以限制自动伸缩范围：

```tsx
<Textarea
  autoSize={{ minRows: 2, maxRows: 6 }}
  style={{ overflowY: 'auto', resize: 'none' }}
/>
```

内容少于最低行数时保留最低高度；超过最高行数后，组件提交的高度不再增加。Textarea 不会根据 `maxRows` 自动修改 `overflow-y`，需要继续访问超出内容时，应由调用方选择 `auto` 或 `scroll`。

不传 `autoSize` 或传入 `false` 时，组件不会写入测量高度：

```tsx
<Textarea rows={4} style={{ height: 160 }} />
```

此时 `rows`、CSS 高度和浏览器 resize 行为保持原生语义。

## 行数约束

`rows` 在自动高度模式下还可以提供最低行数：

- 未启用 `autoSize` 时，`rows` 保持原生 textarea 语义。
- 启用 `autoSize` 且没有有效 `minRows` 时，正整数 `rows` 作为最低行数。
- `minRows` 和 `rows` 同时有效时，以 `minRows` 为准。
- `minRows` 和 `maxRows` 只接受正整数。
- `maxRows` 小于有效最低行数时，按最低行数处理。

`minRows` 和 `maxRows` 可以分别使用：

```tsx
<Textarea autoSize={{ minRows: 3 }} />
<Textarea autoSize={{ maxRows: 8 }} />
```

无效的 `minRows` 或 `maxRows` 会被忽略，并在开发环境输出警告。

## 受控与非受控

Textarea 保留原生的 `value`、`defaultValue` 和 `onChange` 接口。

受控模式下，React 提交新的 `value` 后重新测量：

```tsx
const [value, setValue] = useState('');

<Textarea
  autoSize={{ minRows: 2, maxRows: 8 }}
  value={value}
  onChange={(event) => {
    setValue(event.target.value);
  }}
/>
```

非受控模式下，用户输入会直接调度重新测量：

```tsx
<Textarea autoSize defaultValue="初始内容" />
```

通过 ref 直接修改原生元素的 `value` 属性不会产生 React change 事件，也不会自动触发重新测量。需要程序化更新时，应优先使用受控 `value`。

## 样式与滚动

自动高度完成测量后，组件会在调用方 `style` 之后写入测得的 `height`，因此 `style.height` 会被自动高度覆盖。关闭 `autoSize` 后，组件恢复调用方传入的高度。

以下样式不会被组件接管：

- `overflow-y`
- `resize`
- `min-height` 与 `max-height`
- 字体、行高、字距和换行规则
- padding、border 与 `box-sizing`

CSS 的 `min-height` 和 `max-height` 仍可能约束最终使用高度。达到 `maxRows` 后是否出现滚动条，则取决于调用方设置的 `overflow-y`。

自动高度模式下，用户通过纵向 resize 手柄得到的高度会在下一次测量时被覆盖。需要稳定的自动高度界面时，通常应使用 `resize: none`，或者只允许横向 resize。

## 测量模型

组件使用隐藏的 mirror textarea 复现原始节点的排版。测量过程读取原始 Textarea 的内容、border box width 和相关 computed style，再通过 mirror 的 `scrollHeight` 计算自然高度。

参与测量的样式包括字体、行高、字距、文本方向、换行规则、padding、border 和 `box-sizing`。因此结果来自浏览器对 textarea 的真实排版，不根据字符数量或固定行高推算。

原始值为空时，placeholder 会参与高度测量；值和 placeholder 都为空时，组件仍保留一行输入高度。末尾换行产生的空白行也会计入内容高度。

存在 `minRows` 或 `maxRows` 时，组件会使用另一个单行 mirror 读取当前样式下的一行高度，再把自然高度限制到对应范围。

多个 Textarea 的测量会合并到共享的分阶段布局任务中：先读取原始节点，再统一挂载或更新 mirror，随后读取高度并提交结果。连续请求同一个 Textarea 时，未完成的旧结果会失效。

## 观测与重新测量

启用自动高度后，以下变化会调度测量：

- 受控 `value` 或 `defaultValue` prop 变化。
- 非受控 Textarea 产生用户输入。
- `autoSize`、`minRows`、`maxRows` 或有效最低行数变化。
- Textarea content box width 变化。
- `class`、`cols`、`dir`、`id`、`lang`、`placeholder`、`rows` 或 `wrap` attribute 变化。
- React `style` prop 的内容变化。

组件使用 ResizeObserver 的 border-box 观察模式接收尺寸变化，并以 content box width 判断文本是否需要重新排版。只改变高度、不改变可用宽度时，不会因为 ResizeObserver 再次执行 mirror 测量。

外部样式表内容、祖先 class、继承样式或字体加载发生变化时，如果 Textarea 自身的受观察 attribute 和 content box width 都没有变化，组件不保证重新测量。

Textarea 宽度为 `0` 时无法建立有效的排版测量，组件会保留当前高度。元素重新获得非零宽度并触发尺寸观察后，会再次尝试测量。

首次可信测量完成前，Textarea 使用原生 `rows` 和调用方样式形成初始高度。大量实例中，远离视窗的测量任务可能稍后完成。

## API 参考

### Textarea

渲染原生多行输入元素，并在启用时提交自动测得的高度。

**默认元素：** `textarea`  
**Ref：** `HTMLTextAreaElement`  
**支持 `asChild`：** 否

#### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `autoSize` | `boolean \| { minRows?: number; maxRows?: number }` | `undefined` | 启用自动高度，并可限制最小与最大行数。 |

除 `autoSize` 外，Textarea 支持原生 `textarea` 的属性和事件。自动高度模式会覆盖行内 `height`，其他属性继续转发给原生元素。

### TextareaAutoSizeOptions

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `minRows` | `number` | `undefined` | 自动高度的最低行数；只接受正整数，并优先于原生 `rows`。 |
| `maxRows` | `number` | `undefined` | 自动高度的最高行数；只接受正整数，小于有效最低行数时按最低行数处理。 |

## 边界

- 自动高度只负责计算并写入 `height`，不管理 `overflow-y`、`resize` 或滚动位置。
- `minRows` 和 `maxRows` 只接受正整数。
- 自动高度模式下，`style.height` 会在首次可信测量后被覆盖。
- CSS `min-height` 和 `max-height` 仍然参与最终级联与尺寸约束。
- 只有 Textarea 可用宽度变化才会因 ResizeObserver 重新测量；单独的高度变化不会形成测量循环。
- 通过 ref 直接修改 `value` 不会自动调度测量。
- 不改变 Textarea attribute 或宽度的外部样式与字体变化不保证重新测量。
- 宽度为 `0` 的元素会等待后续可测量尺寸。
