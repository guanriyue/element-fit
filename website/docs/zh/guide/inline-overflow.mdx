# InlineOverflow

`InlineOverflow` 用于测量单行内容是否发生横向溢出，并根据派生的 `overflow` 状态组合附属 UI。它不内置 Tooltip、Popover、展开按钮、具体布局或内容裁剪样式。

它适合表格单元格、名称、路径和标签等宽度受限的单行内容。不适合多行截断、纵向书写模式或复杂 transform。

## 能力边界

`InlineOverflow` 只测量 Root 与 Content 当前形成的真实 DOM 布局，不构造隐藏副本，也不模拟尚未渲染的布局。

“反事实测量”指测量当前 DOM 中并不存在的假设状态。例如，Accessory 尚未渲染，但调用方希望提前知道“如果 Accessory 显示并占用一部分宽度，Content 是否会溢出”。这需要临时构造或模拟另一种布局，不属于 `InlineOverflow` 的能力范围。组件先测量现有布局，再根据结果决定 Accessory 是否渲染。

## 导入

```tsx
import { InlineOverflow } from '@guanriyue/react-fit/inline-overflow';
```

## 测量精度

InlineOverflow 首先使用 `scrollWidth` 和可用宽度进行初步判断。浏览器向 JavaScript 暴露的 `scrollWidth` 和 `clientWidth` 是整数，而文本布局仍然可能落在亚像素边界，因此两者相等或差值很小时，初步结果的置信度不足。

当差值进入 `1 CSS px` 的保守临界区间时，组件会使用 `Range.getBoundingClientRect()` 读取保留小数的内容几何，并完成第二级判断。整数尺寸始终作为第一级判断，Range 只负责校正它无法区分的临界结果。

Range API 是组件规避浏览器尺寸 Bug 的一种解决方案。它读取的是已渲染内容的几何包围盒，而不是浏览器的 ellipsis 状态。该机制适用于普通单行文本和一部分混合 inline 内容；margin、伪元素、定位、transform 和多行排版不属于稳定的测量范围。完整的判断过程、相关社区问题与盒模型处理见 [InlineOverflow 的溢出测量](../implementation/inline-overflow)。

## Accessory

Accessory 只根据 `overflow` 状态显示或隐藏，不参与溢出判定。未溢出时，Accessory 不渲染 DOM 节点；溢出后才挂载并进入调用方定义的布局。

一个 Root 可以包含多个 Accessory。Accessory 必须位于对应 Root 的 React context 中，但 DOM 布局位置不需要与 Content 相邻或同行。

## 单元素模式

如果不需要 Root 和 Content 分别渲染两个 DOM 节点，可以让 Root 使用 `asChild`，并将 Content 作为它的唯一 child。Root 的 ref、`data-overflow` 和 Content 的测量 ref 会合并到同一个元素上。

单元素模式支持直接在共享元素上设置 inline padding。组件会使用同一个元素的 `scrollWidth` 和 `clientWidth` 比较 padding box，并在临界范围内继续使用 content box 和 Range 修正，避免把元素自身的 padding 误判为内容溢出。

## 布局要点

- Root、Content 和 Accessory 都不提供默认样式。
- 调用方需要为 Root 提供宽度约束，并决定 Content 的单行排版与裁剪策略。
- 文本场景需要为 Content 设置 `white-space: nowrap` 或使用等价方式建立单行排版。如果允许换行，结果不再表示单行内容是否放得下。
- `overflow: hidden`、`overflow: clip`、`text-overflow: ellipsis`、渐变遮罩或仅观测状态都由调用方选择。
- flex 布局通常需要为 Content 设置 `min-width: 0`。
- grid 布局通常需要使用 `minmax(0, 1fr)`，或者为 Content 设置 `min-width: 0`。
- Root padding 会参与测量；组件比较 Content 的 `scrollWidth` 与 Root 扣除 inline padding 后的 content box width。
- Root 与 Content 分离时，不要在 Content 上增加 `padding`、`margin` 等会改变布局计算的样式。这类样式会让“内容宽度”和“目标可用宽度”的关系变得不稳定。单元素模式可以在 Root 与 Content 共享的元素上设置 padding。

## 观测边界

组件使用 ResizeObserver 监听 Root 和 Content 的尺寸，并使用 MutationObserver 监听 Content subtree 中的文本和子节点变化。Root 或 Content 元素替换，以及 Content 中的文本或子节点变化，会重新建立测量结果。

MutationObserver 不观察 attributes。只修改 class、style、继承样式、字体或伪元素内容时，如果 Root 的可用宽度和 Content subtree 都没有发生可观测变化，组件不保证重新测量。通过主题 class、响应式 class 或外部样式表改变文本布局时，应在目标交互中验证 overflow 状态是否能够重新建立。

首次可信测量完成前，内部 overflow 状态为 `false`，`data-overflow` 不存在，Accessory 不渲染。当前不提供 `defaultOverflow`、受控 `overflow` 或手动 remeasure API。

## API 参考

### Root

包含 InlineOverflow 的全部部分，默认渲染为 `span`。Root 的 content box 表示 Content 可以使用的目标宽度。

**默认元素：** `span`  
**Ref：** `HTMLElement`  
**支持 `asChild`：** 是

#### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `onOverflowChange` | `(overflow: boolean) => void` | — | 首次可信测量完成后调用；之后在 overflow 状态变化，或者 Root、Content 元素替换并完成新测量时调用。 |
| `asChild` | `boolean` | `false` | 将 Root 的 props、ref 和 overflow 状态合并到唯一 child。 |

除上述属性外，Root 支持 `span` 的原生属性。

#### Data attributes

| Attribute | Value | Condition |
| --- | --- | --- |
| `data-overflow` | `""` | Content 发生横向溢出时存在。 |

### Content

声明唯一的溢出测量节点，默认渲染为 `span`。Content 的单行排版和裁剪样式由调用方提供。

**默认元素：** `span`  
**Ref：** `HTMLElement`  
**支持 `asChild`：** 是

#### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `asChild` | `boolean` | `false` | 将 Content 的 props、ref 和测量行为合并到唯一 child。 |

除上述属性外，Content 支持 `span` 的原生属性。

### Accessory

声明只在 Content 溢出时渲染的附属节点，默认渲染为 `span`。Accessory 不参与溢出判定。

**默认元素：** `span`  
**Ref：** `HTMLElement`  
**支持 `asChild`：** 是

#### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `asChild` | `boolean` | `false` | 将 Accessory 的 props 和 ref 合并到唯一 child。 |

除上述属性外，Accessory 支持 `span` 的原生属性。未溢出时 Accessory 渲染为 `null`，对应子树的状态和 ref 不会保留。

## 边界

- InlineOverflow 只判断横向单行内容，不支持多行截断和纵向书写模式。
- 一个 Root 只应包含一个 Content。Content 是唯一的内容测量节点。
- Root 的 content box 应表达 Content 的目标可用宽度。
- Root 与 Content 分离时，不应在 Content 上增加改变测量语义的 padding 或 margin。
- Accessory 必须位于对应 Root 的 React context 中，但不要求与 Content 相邻或同行。
- Accessory 不参与溢出判定；渲染后占用的空间不会反向改变判定基准。
- Range 临界校正只测量已经参与布局的 DOM 内容，不提供任意 DOM 子树的 intrinsic width。
- 复杂 transform、定位、伪元素和浏览器未反映到观测尺寸中的视觉变化不属于稳定测量模型。
