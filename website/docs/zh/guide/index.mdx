# 组件指南

Element Fit 围绕元素当前获得的真实可用空间组织响应式布局。组件不要求业务先把容器映射成 viewport breakpoint，而是让网格、内容或操作根据所在元素的宽度决定当前展示方式。

组件大致分为两类：`FitGrid` 主要组合 CSS Grid 能力，由浏览器直接完成自适应布局；其他组件会根据真实 DOM 尺寸、内容变化或溢出状态执行测量，并把视觉样式和业务交互继续交给调用方控制。

## 选择组件

| 目标 | 推荐组件 |
| --- | --- |
| 根据每一项的最小可用宽度自动调整 Grid 列数 | [FitGrid](./fit-grid) |
| Grid 变得紧凑时，把额外操作移动到最后一个有效插槽 | [CompactGrid](./compact-grid) |
| 在完整和紧凑两套视图之间选择能够放下的方案 | [FitSwitch](./fit-switch) |
| 保留前部操作，把横向空间放不下的尾部操作交给自定义菜单 | [OverflowList](./overflow-list) |
| 判断单行内容是否发生横向溢出，并组合 Tooltip 或 Accessory | [InlineOverflow](./inline-overflow) |
| 限制 inline 内容的可见行数，并在溢出时渲染 suffix | [LineClamp](./line-clamp) |
| 保留原生 textarea 用法，同时根据内容和宽度自动调整高度 | [Textarea](./textarea) |

## 容易混淆的组件

### FitGrid 与 CompactGrid

`FitGrid` 只负责根据最小 Item 宽度生成自适应 Grid。`CompactGrid` 使用相同的列布局，并额外观察当前列数和 Item 结构，在紧凑条件成立时把 `Extra` 移动到最后一个有效的 `ExtraSlot`。

### FitSwitch 与 OverflowList

`FitSwitch` 在两套完整视图之间切换，例如“图标 + 文案”和“只有图标”。`OverflowList` 面向一组有顺序的操作，空间不足时保留连续的前部 Item，并把尾部 Item 的业务数据交给调用方渲染更多菜单。

### InlineOverflow 与 LineClamp

`InlineOverflow` 观测单行内容在横向空间中是否溢出，不负责裁剪样式。`LineClamp` 面向多行 inline 内容，负责行数限制、溢出测量和末行 suffix 布局。
